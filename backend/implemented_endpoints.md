# توثيق مسارات (Endpoints) الباك اند - HelpDesk Lite

هذا الملف يحتوي على توثيق كامل لجميع الـ Endpoints التي تم تنفيذها وتحديثها في المشروع وفقاً لأحدث التعديلات لضمان توافقها 100% مع المتطلبات.

> **الـ Base URL:** `/api`
> **شكل الاستجابة (Response) الموحد:**
>
> - في حالة النجاح: `{ "success": true, "message": "...", "data": {...} }`
> - في حالة الخطأ: `{ "success": false, "message": "...", "errors": [ ... ] }`

---

## 1. قسم المصادقة (Auth Module)

الـ Base Path: `/api/auth`

### 1.1 تسجيل الدخول `POST /login`

- **الصلاحية (Access):** Public
- **البيانات المطلوبة (Body):**
  ```json
  {
    "email": "user@example.com",
    "password": "123456"
  }
  ```
- **المنطق (Logic):**
  - يتحقق من وجود الإيميل.
  - يقارن كلمة المرور المشفرة (bcrypt).
  - يُصدر رمز JWT صالح لمدة يوم واحد (1d) يحتوي على `id` و `role`.
- **الاستجابات (Responses):**
  - `200 OK`: تسجيل دخول ناجح ويرجع بيانات المستخدم مع الـ `token`.
  - `400 Bad Request`: نقص في البيانات المدخلة.
  - `401 Unauthorized`: الإيميل أو كلمة المرور غير صحيحة.

### 1.2 تسجيل حساب جديد `POST /register`

- **الصلاحية (Access):** Public
- **البيانات المطلوبة (Body):**
  ```json
  {
    "name": "Ahmed",
    "email": "user@example.com",
    "password": "123456",
    "role": "requester" // اختياري، القيم: requester, staff, manager
  }
  ```
- **الاستجابات (Responses):**
  - `201 Created`: تم إنشاء الحساب ويرجع الـ `token`.
  - `400 Bad Request`: نقص البيانات أو الإيميل مسجل مسبقاً.

## 2. قسم التذاكر (Tickets Module)

الـ Base Path: `/api/tickets`
جميع هذه المسارات تتطلب إرسال هيدر المصادقة: `Authorization: Bearer <token>`

### 2.1 إنشاء تذكرة جديدة `POST /`

- **الصلاحية (Access):** أي مستخدم مسجل الدخول (Auth).
- **البيانات المطلوبة (Body):**
  ```json
  {
    "category": "Software", // 'Hardware', 'Software', 'Access', 'Other'
    "description": "تفاصيل المشكلة هنا، يجب أن تكون 10 أحرف على الأقل."
  }
  ```
- **المنطق (Logic):**
  - يتم استخراج `requester` تلقائياً من التوكن (لا يمكن تزويره).
  - يتم تعيين الحالة الأولية `New` ولا يوجد `owner` (Unassigned).
  - يجب ألا يقل الوصف عن 10 أحرف.
- **الاستجابات (Responses):**
  - `201 Created`: تم إنشاء التذكرة بنجاح.
  - `400 Bad Request`: نقص في البيانات، تصنيف غير صحيح، أو الوصف قصير.

### 2.2 عرض تذاكر المستخدم الحالي `GET /my`

- **الصلاحية (Access):** حسابات من نوع `requester` فقط.
- **معاملات البحث (Query Params) - اختياري:**
  - `?status=New`: لفلترة التذاكر بناءً على حالة معينة (New, In Progress, Resolved, Closed).
- **المنطق (Logic):**
  - يُرجع فقط التذاكر التي يكون فيها `requester` هو المستخدم الحالي.
- **الاستجابات (Responses):**
  - `200 OK`: قائمة التذاكر الخاصة بالمستخدم.

### 2.3 عرض جميع التذاكر `GET /`

- **الصلاحية (Access):** `staff` و `manager` فقط.
- **معاملات البحث (Query Params):**
  - `?status=New` أو `all`: لفلترة التذاكر حسب حالة محددة.
  - `?open=true`: لجلب جميع التذاكر المفتوحة فقط (أي حالة غير `Closed`).
- **الاستجابات (Responses):**
  - `200 OK`: قائمة بكل التذاكر في النظام.
  - `403 Forbidden`: إذا حاول Requester الدخول.

### 2.4 ملخص حالات التذاكر `GET /summary`

- **الصلاحية (Access):** `manager` فقط.
- **المنطق (Logic):**
  - يقوم بتجميع عدد التذاكر لكل حالة (`New`, `In Progress`, `Resolved`, `Closed`).
  - يعيد العدد 0 للحالات التي لا تحتوي على تذاكر.
- **الاستجابات (Responses):**
  - `200 OK`: إحصائية بحالات التذاكر.

### 2.5 عرض تفاصيل تذكرة محددة `GET /:id`

- **الصلاحية (Access):**
  - `staff` و `manager`: يمكنهم رؤية أي تذكرة.
  - `requester`: يمكنه فقط رؤية التذاكر الخاصة به.
- **الاستجابات (Responses):**
  - `200 OK`: تفاصيل التذكرة مع بيانات المنشئ والمسؤول.
  - `403 Forbidden`: إذا حاول Requester رؤية تذكرة لا تخصه.
  - `404 Not Found`: إذا كانت التذكرة غير موجودة.

### 2.6 تعيين أو إعادة تعيين مسؤول للتذكرة `PATCH /:id/assign`

- **الصلاحية (Access):** `staff` و `manager`.
- **البيانات المطلوبة (Body):**
  ```json
  { "ownerId": "65b2a2a1..." }
  ```
- **المنطق (Logic):**
  - يجب أن يكون `ownerId` لمستخدم موجود فعلياً في قاعدة البيانات ودوره `staff` أو `manager` (لا يمكن تعيين requester كمسؤول).
- **الاستجابات (Responses):**
  - `200 OK`: تم التعيين بنجاح.
  - `404 Not Found`: التذكرة غير موجودة.
  - `422 Unprocessable Entity`: إذا كان `ownerId` غير صالح (ليس staff أو manager).

### 2.7 تحديث حالة التذكرة `PATCH /:id/status`

- **الصلاحية (Access):** `staff` و `manager`.
- **البيانات المطلوبة (Body):**
  ```json
  { "status": "In Progress" }
  ```
- **المنطق والقواعد الصارمة (Business Logic):**
  1. **الترتيب الإلزامي للحالات:** التذاكر يجب أن تمضي في مسار خطي فقط (`New → In Progress → Resolved → Closed`). لا يمكن تخطي حالة أو الرجوع لحالة سابقة.
  2. **صلاحية الإغلاق (Closed):** فقط أصحاب دور `manager` يحق لهم نقل التذكرة إلى الحالة `Closed`.
  3. **حل التذاكر (Resolved):** مسموح لكل من `staff` و `manager`.
- **الاستجابات (Responses):**
  - `200 OK`: تم التحديث بنجاح.
  - `400 Bad Request`: حالة غير صحيحة.
  - `403 Forbidden`: إذا حاول `staff` إغلاق تذكرة.
  - `404 Not Found`: التذكرة غير موجودة.
  - `409 Conflict`: إذا كانت الحالة المطلوبة تخل بالترتيب الخطي للحالات.
